# 추가 연습 배분 후보 요인의 측정과 선정 설계

8개 후보를 측정 가능한 지표로 정의하고, 기존 자료 점검·공통 짧은 진단·새 원래 seed에서의 예측 확인·비용을 포함한 배분 검증으로 좁히는 설계다. 현재 성능을 기본 입력으로 유지하고 선택적인 핵심 요인은 최대 3개로 제한한다. 신뢰도 F07과 행동 구조 F08은 별도 역할로 평가한다.

- [8개 후보별 설계와 최종 선정 절차](research_design_ko.md)
- [측정 시점, 후보, 기준과 규모를 기록한 protocol](protocol.json)
- [비용·설계 계산기](check_design.py): 비용과 혼합비·조건 수·문서 링크를 계산하고 매번 새로운 `results/`에 소스와 hash를 보존한다. 학습 실행기는 아니다.

첫 단계는 기존 12개 출발 상태와 checkpoint의 점검이다. 공통 4k 진단의 제안 규모는 180개·720k 학습 step이며, 충분한 측정을 위한 개발용 평가를 포함한 환경 비용 상한은 8.40M step이다. 후보당 별도의 완주 실험을 처음부터 8번 수행하는 구조가 아니다.

새 원래 seed를 사용하는 확인 단계와 실제 배분 비교는 앞 단계에서 후보가 남았을 때 진행하는 별도 제안이다. 표본 수 8은 규모 계산 예시이며 검정력을 보장하지 않는다. 자세한 비용과 중단 기준은 설계 본문에 있다.

온라인 예시는 4k probe 하나 + 과제당 2회 평가(최대 4k)로 진단을 최대 8k 안에 맞춘다. 개발용 과제당 20회 평가에서만 예측력이 높은 후보는 저비용 배분 요인으로 확정하지 않는다.

계산 재현: 저장소 루트에서 `python 23_candidate_factor_screening_design_v1/check_design.py`를 실행한다. [실행별 계산과 출처 기록](results/)에 규모 표, 검사 내역, 소스 사본과 SHA-256을 보존한다. 여기서 통과하는 검사는 설계의 산술·참조 확인이며 과학적 효과의 증거가 아니다.

이 버전은 설계만 저장한다. 실제 학습·환경 평가·모델 변경은 없고, 기존 파일럿과 08·19·21·22 버전은 보존한다. 전달 후의 구현이나 설계 변경은 새 독립 버전에서 관리한다.

# 사전학습 로봇의 추가 연습 배분을 검증하는 로컬 파일럿

작성일: 2026년 10월 7일  
버전: v0.1  
상태: 실행 전 설계안. 우선 실행 범위는 개발 확인 P0와 동일 checkpoint의 10개 분기다. 코드 구현과 학습 실행은 별도 단계다.

## 연구 목적과 범위

핵심 질문은 다음과 같다.

> 사전학습된 로봇에게 추가 연습 기회가 제한되어 있을 때, 어떤 과제를 더 연습해야 전체 성능이 가장 많이 개선되는가?

첫 실험에서는 LLM 감독자를 만들지 않는다. 먼저 과제 선택을 잘해서 얻을 수 있는 이득이 있는지, 그 이득을 간단한 수치 신호로 설명할 수 있는지 확인한다. 가장 못하는 과제와 지금 더 연습할 가치가 높은 과제가 일치하는지가 주요 관찰 대상이다.

| 질문 | 확인하려는 내용 | 이 단계만으로 주장할 수 없는 것 |
| --- | --- | --- |
| Q1 배분 효과 | 동일 출발 상태에서 연습 배분에 따라 전체 개선량이 달라지는가? | 적응형 감독자가 필요하다는 결론 |
| Q2 상황 의존성 | 항상 같은 배분이 좋은가, 학습 상태에 따라 유리한 배분이 바뀌는가? | 단순한 학습 시점별 schedule보다 낫다는 결론 |
| Q3 예측 가능성 | 실패율이나 최근 학습 진행량으로 좋은 배분을 고를 수 있는가? | LLM이나 의미 정보가 필요하다는 결론 |

여기서 사전학습 정책은 네 과제를 균등하게 연습한 작은 공유 정책이다. 대규모 RFM이나 공개 VLA checkpoint가 아니다. 이 파일럿은 이미 연습한 과제들의 추가 학습을 다루며, 새 로봇이나 미경험 과제로의 전이를 검증하지 않는다.

기존 [RFM 문헌 검토](RFM_SELF_DIRECTED_LEARNING_REVIEW_20261002.md)에서 다룬 큰 질문의 선행 조건을 저비용 모델로 확인하는 설계다. [Spark용 RFM 파일럿](RFM_PRACTICE_SELECTION_PILOT_DESIGN_20261002.md)을 대체하거나 같은 실험으로 합산하지 않는다. 그 문서의 LIBERO, GRPO, LoRA, 의미 정보 및 확인 분기 설정은 이번 실험에 적용하지 않는다.

## 공통 환경과 학습 설정

### 네 과제와 공유 정책

| 과제 ID | 환경 | 조작 |
| --- | --- | --- |
| DO | drawer-open-v3 | 서랍 열기 |
| DC | drawer-close-v3 | 서랍 닫기 |
| WO | window-open-v3 | 창문 열기 |
| WC | window-close-v3 | 창문 닫기 |

이 과제들은 MetaWorld의 조작 과제다. 여기서는 관련 기술 간 개선과 간섭을 관찰하기 위한 사용자 정의 네 과제 집합으로 사용한다. 공식 MT10 결과나 공식 MT4 벤치마크라고 부르지 않는다. 이 조합에서 배분 효과가 나타난다는 것은 아직 가설이다. [공식 과제 설명](https://metaworld.farama.org/benchmark/task_descriptions/)

네 개의 독립 정책이 아니라 하나의 공유 actor와 공유 critic들을 사용한다. actor와 critic 모두 환경 상태 및 과제 one-hot ID를 입력받는다. 과제별 독립 모델로 바꾸면 다른 기술의 유지와 과제 간 간섭을 보는 현재 질문이 달라진다.

| 항목 | 개발용 설정안 |
| --- | --- |
| 알고리즘 | Stable-Baselines3 SAC를 기준으로 하는 task-conditioned SAC |
| 관측 | 목표가 관측되는 환경 상태 벡터 + 과제 one-hot ID; 이미지 미사용 |
| 네트워크 | actor와 critic의 은닉층 각각 256, 256 |
| 학습 보상 | 설치한 환경 버전의 기본 dense reward |
| 학습 episode | 500 환경 steps, 성공 후 조기 종료하지 않음 |
| Replay | 용량 100,000 transitions, 유효 항목에서 균등 sampling |
| Batch size | 256 |
| Learning rate | 상수 3e-4 |
| Learning starts | 최초 사전학습의 1,000 steps; 분기에서 다시 warm-up하지 않음 |
| 업데이트 | warm-up 이후 환경 transition 1개당 SAC train iteration 1회 |
| Entropy | SAC의 자동 temperature 조절을 공통으로 사용 |
| 평가 행동 | deterministic policy, 추가 exploration noise 없음 |
| 실행 방식 | 우선 학습 프로세스 1개, 분기들은 순차 실행 |

SAC의 MLP와 replay 기반 학습 경로는 공식 구현을 사용하되, 위 숫자는 이 네 과제에 검증된 최적 설정이 아니다. 나머지 SAC 옵션, 정규화 여부, 환경 wrapper, 패키지 버전 및 코드 revision도 P0 전에 resolved config로 고정한다. 숨은 기본값이 실행별로 달라져서는 안 된다. [SB3 SAC 문서](https://stable-baselines3.readthedocs.io/en/master/modules/sac.html)

Dense reward는 sparse 탐색 실패와 연습 배분 효과를 우선 분리하기 위한 선택이다. MetaWorld는 shaped reward를 제공한다. 이전 SABER의 sparse reward 설정과 결과를 직접 합산하지 않는다. [보상 설명](https://metaworld.farama.org/benchmark/reward_functions/)

### 변경하는 것과 고정하는 것

변경하는 것은 다음에 새 경험을 수집할 과제의 비율뿐이다. 보상, 과제 내부 reset 분포, action 범위, exploration 설정, actor와 critic loss, replay sampling 규칙, 학습률과 update 비율은 후보 간 동일하게 둔다. HER, PER, SABER, LLM, VLM은 추가하지 않는다.

새로 수집한 과제가 달라지면 replay 내용과 실제 학습 batch 구성도 달라진다. 이는 배분 개입의 결과이며, replay sampling 규칙까지 같다고 해서 batch의 과제 비율이 같아야 하는 것은 아니다. 이 실험은 고정된 SAC 학습기에서 수집 배분을 바꾼 총효과를 측정한다.

500-step 고정 길이 학습에서 시간 제한은 truncation으로 처리하고 성공 신호와 termination을 혼동하지 않는다. 예상하지 않은 조기 종료, NaN, reset 실패로 실제 step 배분이 달라지면 해당 실행을 정상 완료로 처리하지 않는다.

## 개발 확인 P0

### 실행 순서

1. 개발용 사전학습 seed 901을 사용한다. 네 과제를 균등하게 배분하여 최대 400k steps 학습한다.
2. 0, 100k, 200k, 400k에서 과제당 20 episode의 공개 진단을 수행한다. 0은 학습 전 정책이며 사전학습 비용에 추가 학습 steps를 더하지 않는다.
3. 200k와 400k의 학습 상태를 저장한다. 200k에서 최소 두 과제에 성공과 실패가 모두 관측되면 200k를 첫 분기점으로 사용한다.
4. 200k가 위 조건을 만족하지 않으면 400k에 같은 기준을 적용한다. 둘 다 만족하지 않으면 10분기 실행을 보류한다.
5. GPU 메모리, 학습 steps/sec, 평가 steps/sec, 저장과 복원 시간을 따로 측정한 뒤 첫 10분기의 예상 비용을 계산한다.

이 checkpoint 기준은 개선 여지가 있는지 보는 개발용 선별 규칙이다. 성공과 실패가 섞였다고 추가 학습 가능성이 증명되는 것은 아니다. 학습 전후 성능, update와 파라미터 변화도 함께 확인한다. 전혀 학습하지 못한 정책이나 거의 모든 기술이 포화된 정책은 현재 질문을 판별하기 어렵다.

분기 결과를 본 뒤 유리한 checkpoint로 옮기지 않는다. P0에서 환경이나 hyperparameter를 바꿔야 하면 이유와 버전을 남기고 P0를 다시 수행한다. seed를 바꿔가며 성공한 경우만 선택하지 않는다.

### 구현 사전검증

- 학습 관측에 실제 task ID와 목표가 올바르게 연결되는지 확인한다. 환경별 관측과 action shape 및 스케일을 검사한다.
- 8 episode 블록에서 계획한 과제별 step 수가 정확한지 검사한다. 성공 후 조기 종료 wrapper가 학습에 끼어들지 않아야 한다.
- 과제별 transition이 replay에 저장되고 실제 gradient update에 사용되는지 확인한다. 유효 replay 길이, update 수, 파라미터 변화와 finite loss를 기록한다.
- 같은 배분의 연속 실행과 저장 후 재개 실행을 비교한다. 관측, action, replay 위치, sampled index, update counter와 파라미터가 정한 허용 오차 안에서 일치해야 한다.
- checkpoint는 해당 transition 저장과 모든 예정 update가 끝난 뒤 생성한다. 평가가 학습 RNG나 replay, 정규화 통계를 바꾸면 안 된다.
- 실제 환경 버전, reward 설정, train과 eval 종료 조건을 manifest에 기록한다. task 이름만으로 동작이 같다고 가정하지 않는다.

기술 검사가 실패하면 중단한다. 검사 통과는 과학적 가설의 성공과 다르며, P0에서 어느 과제가 좋아지는지를 smoke 성공 조건으로 삼지 않는다.

## 첫 분기 실험

### 다섯 연습 배분

| 후보 | DO | DC | WO | WC | 8 episode 블록의 개수 |
| --- | ---: | ---: | ---: | ---: | --- |
| U | 25% | 25% | 25% | 25% | 2, 2, 2, 2 |
| F_DO | 62.5% | 12.5% | 12.5% | 12.5% | 5, 1, 1, 1 |
| F_DC | 12.5% | 62.5% | 12.5% | 12.5% | 1, 5, 1, 1 |
| F_WO | 12.5% | 12.5% | 62.5% | 12.5% | 1, 1, 5, 1 |
| F_WC | 12.5% | 12.5% | 12.5% | 62.5% | 1, 1, 1, 5 |

각 블록은 4,000 steps다. 블록 안의 episode 순서는 사전에 정한 난수로 섞는다. 40k 추가 학습은 10블록, 80 episode이며 균등 배분은 과제당 20 episode, 강조 배분은 50, 10, 10, 10 episode가 된다.

한 과제만 100% 연습하는 후보는 초기 실험에 넣지 않는다. 첫 질문은 다른 기술을 최소한 연습하면서 비율을 바꾸는 것이 유익한가이다. 따라서 다섯 후보 밖의 최적 배분을 찾았다고 주장할 수 없다.

### 분기 예산과 복원

- 출발점: P0에서 정한 동일 checkpoint 1개.
- 후보별 추가 학습: 40,000 환경 transitions 및 동일한 update 계약.
- 결과 평가: 분기 전, 추가 20k, 추가 40k.
- 후속 학습 반복: 후보당 2개. 출발 정책은 같고 이후 수집과 학습의 난수를 달리한다.
- 전체: 5후보 x 2반복 = 10분기, 추가 학습 400,000 steps.

복원 대상에는 actor, critic, target critic, 모든 optimizer, entropy coefficient와 그 optimizer, replay 내용과 쓰기 위치, 누적 step과 update counter, 정규화 상태, 관련 RNG 상태가 포함된다. 모델 weight만 복사하지 않는다.

첫 분기는 episode 경계에서 시작하고 다음 과제의 reset을 통제한다. 같은 반복 안에서는 후보 간 가능한 공통 reset 및 난수 입력을 사용하고, 서로 다른 반복은 독립적으로 설정한다. 배분이 다르면 방문 상태와 경험은 달라지므로 같은 seed가 같은 trajectory를 뜻하지는 않는다. 평가용 RNG는 별도로 둔다.

### Replay 노출 확인

62.5%는 새로 수집하는 경험의 비율이다. 기존 경험이 남아 있는 SAC batch에서 해당 과제가 곧바로 62.5%를 차지하지는 않는다.

분기 시작 시 가득 찬 100k replay에 40k transitions를 추가하면 끝의 새 경험 비율은 40%다. 학습 기간 전체에 걸친 평균 노출 비율은 이보다 작다. 과제별 실제 batch 비율과 분기 이후 새 경험 비율을 기록하여, 배분 변경이 실제 학습에 전달되는지 확인한다.

효과가 없다는 결과를 본 뒤 특정 후보만 buffer 크기나 replay 비율을 바꾸지 않는다. 노출이 부족한지 추가 조사하려면 모든 후보에 같은 변경을 적용한 별도 실험으로 다룬다.

## 평가와 분석

### 평가 환경과 정보 분리

평가에서는 항상 네 과제를 동일하게 중요하게 취급한다. 어떤 과제를 많이 연습했는지와 무관하게 각 과제 성공률을 25%씩 반영한다. 공식 `info["success"]`가 episode 중 한 번이라도 1이면 성공으로 센다. 평가에는 성공 시 조기 종료를 허용하며 실제 비용을 기록한다. [MetaWorld 평가 정의](https://metaworld.farama.org/evaluation/evaluation/)

| 용도 | 과제당 episode 수 | 사용 범위 |
| --- | ---: | --- |
| 공개 진단 bank | 20 | checkpoint 확인, 실패율 및 학습 진행량 기반 선택 |
| 결과 평가 bank | 50 | 분기 전후 성능과 후보 비교; 선택기 입력으로 제공하지 않음 |

두 bank는 같은 과제 내부 분포에서 서로 다른 초기 상태로 사전 생성한다. 결과 평가 bank는 모든 후보와 반복에서 동일하게 사용하며 학습에 넣지 않는다. 초기 상태나 task 파라미터의 hash를 남겨 seed만 다르고 물리적 초기 상태는 같은 오류를 검사한다. 평가 bank는 새로운 과제나 OOD 분포가 아니다. 이 사용자 정의 평가를 공식 MT10 전체 프로토콜의 재현이라고 표현하지 않는다.

공개 진단에 기반한 규칙의 추천과 입력 hash는 분기 학습 전에 저장한다. 결과 평가 점수나 분기별 학습 반응을 본 뒤 이 추천을 고쳐서는 안 된다.

### 주요 지표

`c`는 출발 checkpoint, `p`는 배분 후보, `r`은 후속 학습 반복, `h`는 추가 학습 steps, `S_i`는 과제 i의 성공률이다. `BaseSuccess_i(c)`는 분기 전 성공률이다. 성공률은 0부터 1까지로 저장하고, 차이를 percentage points로 표시할 때만 100을 곱한다.

```text
BaseMacro(c) = mean_i BaseSuccess_i(c)
Macro(c, p, r, h) = mean_i S_i(c, p, r, h)
Gain(c, p, r, h) = Macro(c, p, r, h) - BaseMacro(c)
ExtraGain(c, p, r, h) = Gain(c, p, r, h) - Gain(c, U, r, h)
MaxDrop(c, p, r, h) = max_i max(0, BaseSuccess_i(c) - S_i(c, p, r, h))
```

Primary는 40k에서의 `ExtraGain`이다. 시작점 대비 실제 개선량 `Gain`도 반드시 함께 보고한다. U가 하락한 상황에서 U보다 덜 하락한 것을 절대적인 성능 개선이라고 부르지 않는다. 20k는 짧은 예산에서의 보조 결과이며 둘 중 유리한 시점을 사후 primary로 선택하지 않는다.

| 지표 | 얻으려는 정보 |
| --- | --- |
| 40k Macro, Gain, ExtraGain | 제한된 추가 예산에서의 전체 성능과 U 대비 이득 |
| 과제별 시작점 대비 성공률 변화 | 강조한 과제의 개선과 다른 기술의 유지 |
| 과제별 U 대비 성공률 차이 | 동일 예산에서 배분을 바꾼 효과 |
| 최악 과제 성공률과 최대 하락폭 | 평균에 가려진 성능 저하 |
| 20k와 40k의 후보 순위 및 차이 | 이득이 나타나는 속도와 예산에 따른 순위 변화 |
| 두 반복의 후보별 차이와 순위 | 효과의 일관성 및 label의 불안정성 |
| 실제 수집과 batch의 과제 구성 | 계획된 개입이 학습에 반영되었는지 |
| 학습과 평가 시간 및 실제 steps | 비용과 병목 |

현재 세 평가 시점만으로 정밀한 학습 곡선이나 wall-clock AUC의 우월성을 주장하지 않는다. 50 episode의 평가 역시 작은 차이를 확정해주지 않는다. episode별 결과와 짝지은 성공 변경 건수를 남겨 평가 불확실성을 확인한다.

### 과제별 변화표

행은 U 및 각 강조 배분, 열은 네 평가 과제로 놓는다. 각 칸에 시작 전 성공률, 40k 성공률, 시작점 대비 변화, U 대비 차이를 기록한다.

- 시작점보다 성능이 낮아진 경우만 기술의 망각 또는 성능 저하로 분류한다.
- U보다 낮지만 시작점보다 높으면 덜 개선된 것이며, 망각과 구분한다.
- 특정 과제를 강조하면서 다른 과제를 덜 연습한 효과가 함께 들어간다. 이 표를 한 과제 학습의 독립적인 인과적 전이 효과로 해석하지 않는다.

### 간단한 선택 규칙

첫 10분기에서는 다음 규칙을 비교한다. 규칙이 선택한 후보의 실제 분기 결과를 조회하므로 추가 RL 실행은 필요하지 않다.

| 규칙 | 분기 전 선택 방법 |
| --- | --- |
| Uniform | 항상 U |
| Failure | 공개 진단 성공률이 가장 낮은 과제의 강조 후보 |
| Progress | 최근 두 공개 진단 사이에서 단위 학습 step당 성공률이 가장 많이 증가한 과제의 강조 후보 |

Failure에서 최하위가 동률이면 U를 선택한다. Progress에서 양의 증가가 없거나 최댓값이 동률이면 U를 선택한다. 200k는 100k와, 400k는 200k와 비교하고 간격으로 나눈다. 이 Progress는 단순 수치 규칙이며 ALP-GMM 구현을 대신한 정식 비교군은 아니다.

사후에 모든 후보를 알고 고르는 최적 선택은 진단용이다. 반복 1의 40k 결과에서 후보를 고른 뒤 반복 2에서 그 후보를 평가하고, 반대 방향도 계산한다. Argmax 동률은 사전 순서 U, F_DO, F_DC, F_WO, F_WC로 해소한다. 이 교차 반복 결과는 가능한 선택 이득의 불확실한 진단이지, 실제 운영 가능한 감독자나 성능 상한의 보장이 아니다.

한 반복에서 최고를 골라 그 반복의 최고 점수만 보고하지 않는다. 또한 열 개의 분기는 열 개의 독립적인 사전학습 정책이 아니라 한 출발 상태에서 나온 결과다.

## 조건부 확장

첫 분기에서 기술적 문제가 없고 배분 차이가 관찰되면, 차이의 크기, 두 반복의 방향, 비용을 함께 보고 확장 여부를 정한다. 작은 pilot에서 유의확률 하나로 진행을 결정하지 않는다. 결과가 불안정하면 바로 후보나 모델을 늘리기보다 평가 오차, 후속 학습 변동, 실제 노출 부족을 구분한다.

확장안은 새로운 사전학습 seeds 11, 12, 13 각각의 200k와 400k checkpoint를 사용하는 것이다. P0에서 학습 시점을 변경했다면 새 버전에서 두 시점을 먼저 동결한다. 확장 seed의 결과를 보고 시점을 따로 고르거나 포화된 seed를 제외하지 않는다.

```text
3 original training seeds
x 2 checkpoints
x 5 allocation candidates
x 2 continuation repeats
= 60 branches
```

이 단계의 추가 분기 학습은 2.4M steps이며, 세 seed의 400k 사전학습 1.2M steps와 평가 비용은 별도다. 첫 10분기를 포함한 수가 아니며 자동 실행하지 않는다.

확장 자료에서는 다른 사전학습 seed의 결과만 사용해 정한 전역 Fixed와 학습 시점별 Fixed schedule을 비교한다. 전체 자료에서 고른 최고 fixed를 같은 자료에 평가하지 않는다. 학습 데이터에서는 `ExtraGain`의 평균으로 후보를 고르고 남겨둔 seed에서 평가한다.

상황 의존성을 다음처럼 분리한다.

1. 모든 seed와 시점에서 같은 후보가 유리하면 전역 고정 배분으로 설명할 수 있다.
2. seed마다 좋은 후보가 다르지만 한 seed 안에서는 같으면 seed별 차이가 중심이다.
3. 같은 seed 안에서도 시점별 후보가 다르면 단계에 따른 변화의 후보 증거다. 다른 seed에서 정한 시간별 schedule로 충분한지도 확인한다.
4. 시간, 실패율, 최근 진행량으로 설명되지 않는 반복 가능한 차이가 남아야 추가 상태 정보의 가치를 조사할 근거가 생긴다.

보조 분석으로 반복 1의 두 시점 평균에서 seed별 고정 후보를 고르고 반복 2의 두 시점에서 평가한 값과, 시점별로 따로 고른 값을 비교한다. 역방향도 계산한다. 이 seed별 고정 후보는 미래 시점의 label까지 쓰는 사후 진단이므로 실제 배포 가능한 기준선이 아니다.

통계 집계는 사전학습 seed를 중심으로 한다. 같은 seed의 checkpoint와 두 후속 반복은 묶어서 보고하며 60개의 독립 seed로 세지 않는다. 세 origin seed 역시 확정적인 일반화나 작은 효과의 유의성을 주장하기에는 제한적이므로 개별 seed 결과를 함께 제시한다.

## 실행 예산

첫 실행은 개발용 사전학습을 400k까지 마치고 첫 10분기를 모두 수행하는 경우를 기준으로 계산한다. 평가 steps 상한은 episode당 500 steps이며 성공 시 평가를 조기 종료하면 실제 비용은 줄어든다.

| 항목 | 학습 steps | 평가 episode 수 | 평가 steps 상한 |
| --- | ---: | ---: | ---: |
| 개발 사전학습 | 400,000 | 0 | 0 |
| 공개 진단 0, 100k, 200k, 400k | 0 | 4 x 4 x 20 = 320 | 160,000 |
| 첫 분기점의 결과 평가 | 0 | 4 x 50 = 200 | 100,000 |
| 10분기 추가 학습 | 400,000 | 0 | 0 |
| 10분기 각각 20k와 40k 평가 | 0 | 10 x 2 x 4 x 50 = 4,000 | 2,000,000 |
| 합계 | 800,000 | 4,520 | 2,260,000 |

전체 환경 transitions 상한은 3.06M이다. 설치, smoke, 복원 검사, reset, checkpoint I/O와 실패한 실행의 비용은 별도이며 모두 비용 장부에 남긴다. 이전에 사용한 5병렬 Spark 실행 조건을 로컬 PC에 그대로 적용하지 않는다.

이 설계는 작은 모델을 쓰지만 몇 분 안에 끝나는 실험이라고 보장하지 않는다. 학습과 평가 처리량을 분리 측정하여 실제 시간 예산을 잡는다. 우선 한 프로세스에서 검증하고 병렬화를 변경하면 seed, 자원 경쟁과 처리량 조건을 기록한다.

모든 후보를 분기 학습하는 비용은 연구용 진단 비용이다. 이를 숨기고 실제 감독자가 40k 경험만으로 최적 후보를 알고 있었다고 주장해서는 안 된다. 후속 온라인 선택 실험에서는 선택에 필요한 진단과 검증 비용도 예산에 포함해야 한다.

## 보존할 산출물

다음은 구현 시 생성할 결과물이다. 이 설계 문서 자체가 해당 파일이나 결과를 생성했다는 뜻은 아니다.

| 산출물 | 필수 내용 |
| --- | --- |
| run_manifest.json | 설정 버전과 hash, 코드와 패키지 버전, 환경과 wrapper, hardware, seed 계층, update 계약 |
| preflight.json | 입력과 과제 배분, 종료 처리, gradient, 복원, RNG 분리 검사 결과 및 실패 이유 |
| checkpoint_manifest.json | 사전학습 seed와 step, 전체 학습 상태 경로와 hash, 첫 분기점 선택 근거 |
| selection_rules.json | 각 context의 공개 입력, 시점, 고정 규칙의 추천 후보와 생성 시점 |
| train_metrics.csv | 과제별 실제 수집 수, 성공과 reward, actor와 critic loss, critic별 절대 TD error 요약, entropy coefficient, update 수, batch 과제 구성, 새 경험 비율, 처리 시간 |
| eval_episodes.csv | context, 후보, 후속 반복, 추가 step, bank와 초기상태 hash, 과제, success, return, 실제 episode 길이 |
| branch_summary.csv | before와 after, Gain, ExtraGain, 과제별 변화, 완료 여부, 비용 |
| analysis.md | 실패율과 연습 가치의 대응, 과제별 변화표, 반복 검증, 비용 및 다음 실행 판단 |

실패하거나 중단한 실행도 manifest와 비용을 남긴다. 누락 결과를 0점이나 성공 결과로 바꾸지 않는다. 완료 분기만 보고할 때도 전체 예정 분기 수와 누락 이유를 함께 명시한다.

## 결과 해석과 다음 연구 질문

| 관찰 | 우선 해석 | 다음 단계 |
| --- | --- | --- |
| 배분 차이가 거의 없음 | 현재 과제, 후보, 예산에서 선택 여지가 작거나 검출력이 부족함 | replay 노출, 학습 가능성, 평가 오차를 확인하고 종료 또는 별도 설계 |
| 반복마다 우열이 크게 바뀜 | 후속 학습 또는 평가의 잡음이 선택 이득보다 클 수 있음 | 신호와 잡음을 분리; 불안정한 label로 복잡한 감독자를 학습하지 않음 |
| 동일한 후보가 계속 좋음 | 고정 배분으로 충분할 수 있음 | 다른 seed에서 고른 Fixed로 확인 |
| 실패율이나 Progress가 잘 선택함 | 단순 수치 정보가 충분할 수 있음 | 이를 강한 기준선으로 사용; LLM 필요성을 주장하지 않음 |
| 같은 seed 안에서 유리한 후보가 바뀜 | 상태나 학습 단계에 따른 선택의 여지가 있음 | 시간별 schedule과 현재 측정값의 설명력을 분리 |
| 강조 과제만 좋아지고 전체 평균은 하락 | 다른 과제의 기회비용이나 기술 손실이 중요함 | 전체 이득과 기술 유지를 고려한 선택 가설 |
| 20k와 40k 순위가 뒤집힘 | 남은 연습 예산에 따라 좋은 선택이 달라질 수 있음 | 예산을 조건으로 한 연습 가치 예측 가설 |
| 수치 신호로 구분하기 어려운 반복 가능한 차이가 남음 | 추가 상태 정보가 도움이 될 가능성이 있음 | 실패 단계나 실행 내용을 최소한 추가해 동일 예산에서 비교 |

마지막 경우에도 곧바로 LLM을 붙이지 않는다. 우선 실패 단계 등 제한된 관측의 추가 가치와 단순 수치 선택기의 개선을 검증한다. 그 후에야 같은 정보를 받는 수치 모델, 표현 모델, LLM 또는 VLM의 역할을 나눠 비교할 수 있다.

학습 진행량을 이용한 curriculum과 유용한 환경을 재방문하는 방법은 이미 존재한다. 따라서 배분 효과를 발견했다는 사실 자체가 새로운 알고리즘의 기여는 아니다. [ALP-GMM](https://arxiv.org/abs/1910.07224), [Prioritized Level Replay](https://proceedings.mlr.press/v139/jiang21b.html)

첫 결과 보고서는 다음 다섯 질문에 답한다.

1. 같은 출발점과 예산에서 U보다 유리한 후보가 다른 반복에서도 유지되는가?
2. 그 이득은 특정 기술의 개선, 다른 기술의 개선 또는 손실 중 무엇으로 구성되는가?
3. 가장 못하는 과제를 고르는 규칙과 가장 유익한 연습 후보가 언제 어긋나는가?
4. 차이를 현재 성공률, 최근 진행량, 학습 시점 및 실제 batch 노출로 설명할 수 있는가?
5. 다음 실험은 반복 확인, 추가 관측, 예산 변화, 기술 유지, 또는 연구 방향 종료 중 무엇이어야 하는가?

현재 실행 범위는 P0와 첫 10분기까지다. 가장 중요한 산출물은 우승 후보 하나가 아니라, 현재의 실패 정도와 추가 학습 가치가 언제 어긋나는지 보여주는 검증 가능한 자료다.

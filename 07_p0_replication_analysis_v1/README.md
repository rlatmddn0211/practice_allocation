## 실행과 비교 범위

원래 사전학습 seed 901의 P0 200k 전체 상태 checkpoint에서 모든 분기를 시작했다.
SAC learner, optimizer, replay와 평가 bank를 유지했으며, dense reward 조건도 동일하다.
균등(U)은 과제당 25%, 집중 배분은 해당 과제 62.5%와 나머지 각 12.5%의 새 경험을 수집한다.
분기당 추가 학습은 40,000 step, 결과 평가는 +20k와 사전에 정한 주평가 시점 +40k이다.

그 공개 진단에서 서랍열기 0%, 창문열기 5%였으므로 실패율 규칙은 F_DO이다.

seed 1904에서 U는 42%로 출발점보다 6.5%p 하락했다. 그 seed의 큰 상대 이득에는
균등 배분의 성능 하락을 피한 효과가 포함된다. 탐색적 민감도 분석에서 1904를 잠시
제외해도 F_DC와 F_WO의 평균 차이는 각각 +5.0, +2.0%p였다. 이 분석은 특정 seed를

## 사전에 고정한 보조 관찰

### 서랍열기 자체 집중보다 서랍닫기 집중에서 서랍열기 성능이 높았다

| 새 후속 seed | F_DO의 서랍열기 성공률 | F_DC의 서랍열기 성공률 | 차이 |
| --- | ---: | ---: | ---: |
| 1903 | 8% | 20% | +12%p |
| 1904 | 6% | 10% | +4%p |
| 1905 | 22% | 34% | +12%p |

새 3/3에서 방향이 반복됐다. 기존 발견용 1901·1902도 각각 +16, +14%p로 같은 방향이었다.
서랍닫기는 출발점 평가에서 이미 100%였지만 그 과제에 더 배분한 조건에서 서랍열기가
더 좋아졌다는 관찰이다. 새 경험의 구성, 다른 과제의 연습량, replay 학습이 함께
작용하므로 서랍닫기에서 서랍열기로의 직접적인 전이를 분리해 입증한 실험은 아니다.

### 창문닫기 하락 후 회복 패턴은 보편적으로 반복되지 않았다

F_DO 조건의 창문닫기 성공률은 다음과 같다.

| 새 후속 seed | 출발점 | +20k | +40k | 사전 정의한 하락 후 회복 |
| --- | ---: | ---: | ---: | --- |
| 1903 | 84% | 0% | 100% | 반복 |
| 1904 | 84% | 94% | 100% | 반복 안 됨 |
| 1905 | 84% | 94% | 52% | 반복 안 됨, 후반 하락 |

기존 두 seed에서는 모두 84→0→100%였지만 새 실험에서는 1/3만 반복됐다.
“20k에 낮아도 40k에 회복한다”는 운영 규칙을 둘 근거가 부족하다.
40k 이후에 회복하는지는 이번 실험으로 알 수 없다.

## 연구 판단과 다음 검증

이 출발점에서 “현재 가장 못하는 과제에 더 연습시키면 좋은 배분이 된다”는 규칙은
안정적인 개선을 주지 못했다. 일부 다른 배분의 이득은 새 반복에서도 관측됐으므로
실패율과 추가 연습의 가치를 구분해 측정할 이유가 있다. 다만 고정 F_DC로 충분할
가능성도 남아 있다. 추가 정보를 사용하는 선택기가 필요하거나 유리하다는 결론은 이르다.

다음에는 다른 원래 사전학습 seed와 다른 출발 checkpoint에서 같은 비교를 해야 한다.
F_DC 같은 고정 배분을 강한 기준선으로 두고, 실패율·최근 진행량·학습 시점이 더 좋은
배분을 예측하는지 확인하는 것이 합리적이다. 이 분석에서는 추가 학습을 실행하지 않았다.

제한사항은 원래 seed 1개, checkpoint 1개, 새 후속 seed 3개, 재사용하는 200개 평가 상태다.
범위·방향 일치 횟수는 신뢰구간이나 통계적 유의성 판정이 아니다. 이번 검사는 저장된
episode 결과를 재집계하고 checkpoint 바이트·복원 기록을 대조했으며 정책을 새로
실행해 재평가한 것은 아니다. 구현 검사 통과 횟수는 과학적 효과의 표본 수가 아니다.

## 출처와 재현성

독립 분석 스크립트 [analyze.py](analyze.py)는 04·06의 코드에서 import하지 않는다.
각 실행은 새 `results/<UTC>_analysis_<ID>/`를 만들고 분석 소스 사본·hash, 입력 hash,
설정, 패키지 버전, 비용과 실패 검사를 보존한다. 01~06의 구현과 기존 실행은 수정하지 않았다.

- 새 원자료: `../06_p0_branch_replication_v1/results/20261008T030554Z_branch_replication_cuda_2c28c437/run/`
- 기존 원자료: `../04_p0_allocation_branches_v1/results/20261007T091127Z_allocation_branches_cuda_64ec1ea7/run/`
- 채택 분석: `results/20261008T054416Z_analysis_81118be8/`, 1,127/1,127 통과, 약 3.21초
- 최종 보고서 빌드: `results/20261008T060037Z_report_build_dfe49c9f/`, 상태 `complete`
- 최종 브라우저 검사: `results/20261008T060051Z_report_browser_be63ab24/`, 16/16 통과, 화면 9개 보존

감사는 공통 출발점의 200개 평가 결과, 원래 checkpoint와 고정 입력 hash, 실행 소스,
새 checkpoint 31개와 저장된 복원 검사, 단계별 실제 배분, 40k update 수,
기존·새 평가 10,400개 episode의 집계, 전체 결과 비교표와 비용 장부를 대조했다.
기존 발견 결과를 고정한 19개 입력의 hash도 유지됐다.

처음 분석 실행 `20261008T054110Z_analysis_36253fd2`도 검사에 통과했다.
보고서 출처 설명과 날짜 형식 보완 후 새 디렉터리에서 다시 실행했으며 두 결과를 보존했다.
첫 미리보기 실행 `20261008T055314Z_preview_326648ed`는 Windows 환경변수 Path/PATH
중복으로 실패했다. 실행기를 수정한 뒤 별도 경로에서 성공했다.
첫 브라우저 실행 `20261008T055400Z_report_browser_44b3b3b4`는 샌드박스의 로컬 연결

첫 정상 화면 검사에서 수치는 맞았으나 강조 Markdown 표시 2곳과 좁은 화면의 차트

문자 깨짐·미처리 예외 부재를 확인했다. 앱 내부 자동 열기 도구는 제공되지 않아
로컬 링크와 headless Chrome 확인으로 전달한다.

보고서 소스는 `report_app/src/content/report/`와 `report_app/src/data.json`이다.
공유 보고서 runtime은 data-analytics 1.0.11의 검증된 템플릿을 그대로 사용했으며,

# 연습 배분 후속 실험 설계

2026년 10월 8일 제안. 먼저 새로운 평가 사례로 측정을 확인하고, 독립 사전학습 정책과
학습 시점에서 배분 효과를 검증한다. 그다음 목표 과제의 연습량을 고정한 배분 교환과
과제 구성 변경으로 설명 범위를 좁힌다. 상태에 따라 좋은 배분이 반복적으로 달라지고
단순 고정 배분이나 시간표로 설명되지 않을 때 선택기 연구로 진행한다.

이 폴더는 설계와 예산 계산을 보존한다. 아래 새 학습과 정책 평가는 실행하지 않았다.
원래 [파일럿 설계](../LOCAL_PRACTICE_ALLOCATION_PILOT_DESIGN_20261007.md)와
검증을 마친 01~07 버전은 보존한다. 조건과 seed를 정리한 [protocol.json](protocol.json)은
`proposed_not_executed` 상태다. E4의 선택기 구체화는 앞 단계 결과를 본 뒤 별도로 동결한다.

## 현재 증거가 남긴 질문

| 관찰 | 해석에 필요한 후속 확인 |
| --- | --- |
| 새 후속 seed 3개에서 F_DC와 F_WO가 모두 U보다 높음 | 원래 사전학습 seed 901의 200k에만 유리한 배분인지 |
| F_DC의 DO 성공률이 F_DO보다 기존 2개와 새 3개 모두에서 높음 | DO 자체 연습량 감소와 다른 과제의 연습 효과를 구분할 수 있는지 |
| 새 3개에서 DO 평균은 F_DC 21.33%, F_WO 23.33%, F_DO 12.00% | 서랍 열기·닫기의 유사성만으로 설명하는 것은 성급함 |
| 실패율 규칙 F_DO의 새 평균 이득은 +0.33%p, 1승·2패 | 공개 진단 0/20 대 1/20의 불안정한 순위 때문에 잘못 선택했는지 |
| F_DO의 WC 하락 후 회복은 새 1/3에서만 반복 | 회복을 보장하는 법칙 대신 예산별 개선과 손실을 따로 측정해야 함 |
| F_DC와 F_WO의 U 대비 우열이 20k와 40k에서 달라짐 | 예산에 따른 순위 변화가 다른 출발 정책에서도 반복되는지 |
| 새 경험 비율의 학습 기간 평균은 약 20%, 집중 과제의 batch 비율은 약 32~33% | 새 수집 비율 62.5%와 실제 업데이트의 과제 비율은 다름 |

수치는 [07 분석](../07_p0_replication_analysis_v1/README.md)과
[batch 노출 원자료](../07_p0_replication_analysis_v1/results/20261008T054416Z_analysis_81118be8/replay_exposure.csv)에 근거한다.
기존 두 발견용 반복과 새 세 확인용 반복을 합쳐 새 확인 실험으로 부르지 않는다.
평가 사례를 늘리는 것과 독립 사전학습 정책을 늘리는 것은 서로 다른 불확실성을 줄인다.

연구의 목표는 특정 과제를 항상 더 연습해야 한다는 결론이 아니다.
현재 성능, 과제 관계, 학습 상태와 남은 예산이 추가 연습의 가치를 얼마나 설명하는지,
그 정보로 제한된 예산을 더 잘 배분할 수 있는지를 확인한다.

## 우선순위와 예상 규모

| 단계 | 질문 | 새 사전학습 | 분기 학습 | 평가 episodes | 시간 계획 범위 |
| --- | --- | ---: | ---: | ---: | ---: |
| E0 측정 확인 | 새 평가 사례와 더 정밀한 실패율 진단에서도 관찰이 유지되는가 | 0 | 0 | 10,800 | 0.8~1.5시간 |
| E1 출발 상태 확장 | 다른 원래 seed와 200k·400k에서도 반복되는가 | 1.20M | 90분기, 3.60M | 79,200 | 19~27시간 |
| E2 배분 교환 | DO 연습량을 고정해도 DC와 WO의 배분 교환이 DO를 바꾸는가 | 0, E1 재사용 | 27분기, 1.08M | 22,800 | 4.8~7시간 |
| E3 과제 구성 변경 | 열기·닫기 쌍이 적은 조합에서도 배분을 잘 고를 여지가 있는가 | 1.20M | 90분기, 3.60M | 81,600 | 20~30시간 |
| R 선택적 replay 대조 | 수집 배분과 batch 과제 비율 중 무엇에 민감한가 | 0, E1 재사용 | 36분기, 1.44M | 30,000 | 6.4~9시간 |
| E4 조건부 선택기 검증 | 사전에 고른 규칙이 새로운 원래 seed에서 좋은 배분을 선택하는가 | 1.20M | 최대 108분기, 4.32M | 최대 93,600 | 23~32시간 |

첫 실행 묶음으로 권하는 것은 E0와 E1이다. 총 새 학습 4.80M, 평가 90,000 episodes다.
E2는 이득의 구조를 설명할 때, E3는 과제 조합에 대한 일반성을 우선 확인할 때 진행한다.
E0~E3를 모두 수행하면 새 학습 10.68M이며 R과 E4는 여기에 포함하지 않는다.
모든 단계를 자동 실행하거나 순차 승인된 것으로 간주하지 않는다.

시간은 RTX 3070 단일 worker에서 관측한 400k 사전학습과 600k 분기 실험을 이용한
계획값이다. 사전학습 약 122 step/s, 분기 학습 약 102 step/s를 사용했다. 평가 및
기타 잔여 시간은 episode당 약 0.296초로 환산했지만 이는 순수 평가 처리량이 아니다.
표의 범위는 통계적 신뢰구간이나 완료 시각 보장이 아니며 어려운 새 과제, 긴 평가
episode, 시스템 부하로 늘어날 수 있다. 환경 검증·smoke·실패 실행 비용은 별도 기록한다.

## E0 새로운 평가 사례와 실패율 진단

가설은 현재 관찰이 작은 고정 평가 bank에만 의존하지 않는다는 것이다.
원래 200k 출발점 하나와 저장된 25개 40k 종료 정책을 새 결과 bank에서 재평가한다.
과제당 100개, 정책당 400개이므로 결과 평가 10,400 episodes다. 출발점에 별도의 공개
진단 100개씩을 추가하면 400 episodes이며 총 10,800회다. optimizer와 replay는 바꾸지 않는다.

새 결과 bank와 공개 bank는 서로, 기존 bank와 학습 초기 상태와 구분해 생성하고
상태 파라미터 hash를 고정한다. 기존과 같은 과제 내부 분포의 평가이며 OOD 평가는 아니다.
새 결과에서도 주 비교는 새 후속 seed 1903~1905의 F_DC 대 U이며, DO의 F_DC 대 F_DO,
F_WO 대 U와 전체 표를 함께 보고한다. 기존 1901~1902는 별도 표에 둔다.

공개 진단으로 Failure의 새로운 선택과 입력 hash를 먼저 기록한 뒤 결과 bank를 평가한다.
새 선택의 성능은 다섯 후보 중 해당 분기를 조회할 수 있다. 기존 Failure=F_DO 기록은
그대로 유지하며 새 100사례 규칙을 별도 이름으로 비교한다. 100사례를 재표집해 과거와
같은 20사례 진단에서 과제 순위가 얼마나 흔들리는지도 기술적으로 계산한다.

새 bank에서 차이가 작아지면 그 결과를 받아들이고 평가 오차와 출발점 효과를 분리한다.
원래 결론을 유지하려고 bank나 seed를 재선택하지 않는다. 새 사례를 잘 맞춘다고 원래
사전학습 seed에 대한 일반화가 검증되는 것도 아니다.

## E1 독립 사전학습 정책과 학습 시점

가장 중요한 본 실험이다. 원래 설계의 새 사전학습 seed 11·12·13 및 200k·400k를 유지하고,
후속 학습 변동을 보기 위해 후속 반복을 2개에서 3개로 늘린 별도 확장안이다.
새 사전학습은 네 과제 균등 400k이며 공개 진단을 0·100k·200k·400k에 수행한다.
모든 seed의 200k·400k 전체 상태를 저장하고 두 시점 모두 사전에 정한 비교에 포함한다.

```text
사전학습 3 seed × 400k = 1.20M
3 seed × 2 checkpoint × 5 배분 × 3 후속 seed × 40k = 3.60M
합계 90분기, 새 학습 4.80M
```

후속 seed 표지는 2101·2102·2103이다. 실제 난수 stream은 원래 seed·checkpoint·반복·용도를
포함해 구분하고 같은 context의 배분끼리 가능한 reset 및 난수 입력을 짝짓는다.
같은 seed가 다른 배분에서 같은 trajectory를 만든다고 가정하지 않는다.
E1은 901의 추가 반복과 합산하지 않고 독립 사전학습 정책에 대한 새 결과로 보고한다.

주 대비는 40k의 F_DC−U 평균 성공률 차이다. 각 원래 seed에서 두 checkpoint와 세 반복에
동일 가중치를 주고 최종적으로 원래 seed 세 개를 동일 가중 평균한다.
F_WO−U, F_WC−U, DO에서 F_DC−F_DO, Failure·Progress 선택과 20k 결과는 보조 비교다.
시작점 대비 절대 개선과 과제별 손실도 필수로 보고한다.

다섯 배분을 모두 실행하므로 다음 규칙은 추가 RL 비용 없이 조회 비교할 수 있다.

| 규칙 | 결과를 보기 전에 사용할 정보 |
| --- | --- |
| Uniform | 항상 U |
| Fixed DC | 기존 파일럿으로 고정한 F_DC |
| 학습된 전역 Fixed | 남겨둔 원래 seed를 제외한 다른 원래 seed에서 평균적으로 좋은 배분 |
| 시간별 Fixed | 다른 원래 seed에서 정한 200k용·400k용 배분 |
| Failure | 해당 checkpoint의 공개 100사례 성공률 최하위 과제, 동률이면 U |
| Progress | 공개 진단 100k→200k 또는 200k→400k의 step당 개선량 최대 과제, 양수 최댓값이 없거나 동률이면 U |

학습된 두 Fixed 규칙은 원래 seed 하나 전체를 남겨두는 방식으로 검증한다.
동일 정책의 다른 checkpoint나 후속 seed가 규칙 학습 쪽으로 새어 들어가지 않게 한다.
후보 선택의 동률 순서는 U, F_DO, F_DC, F_WO, F_WC로 고정한다.

최고 후보의 이름이 바뀌었다는 것만으로 상태 의존성을 주장하지 않는다.
각 context에서 후속 반복 두 개로 후보를 고르고 남은 반복에서 평가하는 과정을 교대해,
순위 변화가 후속 학습 잡음을 넘어 반복되는지 본다. 이 결과는 분기 결과를 이용한
사후 진단이며 실제 선택기나 보장된 성능 상한이 아니다.
전역 Fixed와 시간별 Fixed로 충분한지 먼저 확인한 뒤 추가 상태 정보의 가치를 논한다.

## E2 목표 과제 연습량을 고정한 배분 교환

현재 F_DO 대 F_DC 비교는 DO의 연습량까지 달라진다. 또한 기존 F_DC·F_WO·F_WC는 모두
DO 12.5%로 같으므로 이 세 조건의 DO 결과도 먼저 기술적으로 비교해야 한다.
새 세 반복에서 F_WO의 DO 평균이 F_DC보다 높은 점을 숨기고 서랍 쌍의 효과만 강조하지 않는다.

새 대조실험에서는 DO와 WC를 각각 25%로 고정하고 DC와 WO에 배분하는 양만 교환한다.
모든 조건은 8 episode 블록, 4k 단위로 정확히 구현할 수 있다.

| 조건 | DO | DC | WO | WC | 40k에서 DO 학습 |
| --- | ---: | ---: | ---: | ---: | ---: |
| U | 25% | 25% | 25% | 25% | 10k |
| DC 증가 | 25% | 37.5% | 12.5% | 25% | 10k |
| WO 증가 | 25% | 12.5% | 37.5% | 25% | 10k |

E1의 원래 seed 11·12·13의 200k에서 새 후속 seed 2201·2202·2203을 사용한다.
3 출발점 × 3 조건 × 3 반복 × 40k = 27분기, 1.08M이다. U도 새 후속 seed로 실행한다.
주 대비는 40k DO 성공률에서 DC 증가−WO 증가이며, U와의 차이, 시작점 대비 개선,
네 과제 평균 및 최대 하락폭을 함께 본다.

DC 증가 조건이 반복해서 유리하면 DO 수집량 감소만으로 이전 현상을 설명하기 어렵다.
WO 증가도 비슷하거나 더 좋으면 서랍 쌍만의 특별한 관계라는 설명은 약해진다.
어느 조건이든 목표 과제의 수집 수만 같고 정책 변화에 따른 DO 방문 상태는 달라진다.
또한 DC 증가와 WO 감소가 동반되므로 이는 자원 교환의 효과이지 DC의 독립적 직접 전이
효과를 완전히 분리한 것은 아니다.

## E3 과제 구성을 바꾸는 검증

네 과제라는 크기, task one-hot 차원, 공유 SAC, dense reward, 연습 예산을 유지하고
두 새 조합을 각각 처음부터 사전학습한다. A는 E1의 200k 결과를 참조한다.

| 조합 | 과제 | 목적 |
| --- | --- | --- |
| A 기존 | DrawerOpen, DrawerClose, WindowOpen, WindowClose | 열기·닫기 두 쌍의 기준 |
| B 서랍 쌍 유지 | DrawerOpen, DrawerClose, Push, ButtonPress | 서랍 쌍의 관찰이 다른 동반 과제에서도 유지되는지 |
| C 서랍 닫기 교체 | DrawerOpen, PickPlace, Push, ButtonPress | 명시적 열기·닫기 쌍이 없는 조합의 배분 효과 |

B와 C에는 DO·Push·ButtonPress의 세 공통 과제가 있어 이들의 변화도 비교할 수 있다.
다만 DC를 PickPlace로 교체하면 난이도, 상태 분포와 학습 가능성도 바뀐다. C를 수치로
검증된 저유사도 집합이라고 부르거나 B−C 차이를 유사성의 순수 인과 효과로 해석하지 않는다.
선택한 과제들은 [MetaWorld 공식 과제 설명](https://metaworld.farama.org/benchmark/task_descriptions/)에 있는 과제다.

각 새 조합에서 원래 seed 11·12·13을 각각 균등 200k 사전학습한다. 0·100k·200k 공개 진단과
200k의 다섯 배분, 새 후속 seed 2301·2302·2303, 추가 40k를 사용한다.
두 조합 합계는 사전학습 1.20M와 90분기 3.60M, 총 4.80M이다.

같은 숫자의 원래 seed는 가능한 초기화 차이를 줄이는 장치이며 서로 다른 조합의 정책을
같은 출발 정책이라고 부르지 않는다. 주 결과는 조합 내부의 U 대비 이득, 규칙별 선택 결과,
개별 과제 변화다. 서로 다른 조합의 raw macro 순위로 배분 방법의 우열을 판정하지 않는다.
같은 과제의 bank는 재사용할 수 있지만 서로 다른 과제의 평가 사례끼리는 짝짓지 않는다.
C에는 DC가 없으므로 Fixed DC라는 이름으로 다른 과제를 대입하지 않는다. 전역 Fixed와
시간별 Fixed는 해당 조합의 다른 원래 seed에서 배분을 고르고, 조합 간 비교는 규칙의
성능과 regret을 각각의 U 기준으로 보고한다.

공개 진단에서 바닥·천장 효과가 강하더라도 불리한 seed나 과제를 제거하지 않는다.
각 조합의 200k 결과를 예정대로 보고하고, 추가 사전학습이 필요하면 모든 해당 seed에
동일한 예산을 적용하는 별도 조건을 설계한다. 사후에 400k로 바꾸고 원래 200k 계획의
성공으로 취급하지 않는다. B·C는 사용자 정의 MetaWorld 부분집합이며 별도 벤치마크
일반화나 공식 MT10 평가의 재현이 아니다.

## R 선택적 replay 대조

현재 수집 비율 변경은 실제 batch 비율 변경을 동반한다. E1에서 현상이 유지되고 그
작동 경로를 더 알고 싶을 때 2×2 대조를 수행한다.

| 새 경험 수집 | 기존 방식으로 replay 균등 추출 | 과제마다 64개씩 batch 256 추출 |
| --- | --- | --- |
| U | U와 자연스러운 batch 구성 | U와 과제 균등 batch |
| F_DC | F_DC와 자연스러운 batch 구성 | F_DC와 과제 균등 batch |

원래 seed 3개 × 200k × 4조건 × 새 후속 seed 3개 × 40k = 36분기, 1.44M이다.
buffer 용량·내용의 출발 상태, 전체 update 수, 나머지 SAC 설정을 유지한다.
과제 균등 조건은 해당 과제 buffer 내부에서 균등 sampling한다. source hash와 새 규칙을
명시한 별도 구현을 사용하며 E1의 주 결과와 합산하지 않는다.

주 관심은 replay 규칙에 따라 F_DC−U가 얼마나 달라지는지다. 차이가 줄면 batch 과제
가중치에 대한 민감성과 일관되지만, 공유 표현이나 전이가 없다는 증거는 아니다.
actor·critic의 과제별 gradient cosine을 읽기 전용 보조 진단으로 추가할 수 있으나 그 값
자체를 성공률 개선이나 인과적 전이의 증거로 쓰지 않는다. PCGrad는 다중 과제의 gradient
간섭을 다루는 선행 연구다. 이 단계에서 자동으로 PCGrad로 학습기를 바꾸지는 않는다.
[Gradient Surgery for Multi-Task Learning](https://arxiv.org/abs/2001.06782)

## E4 조건부로 진행할 선택기 외부 검증

전역 고정 배분이나 시간별 배분표보다 더 나은 선택의 여지가 후속 반복에서도 남을 때
진행한다. 첫 단계는 checkpoint에서 한 번 선택해 40k 동안 유지하는 규칙의 검증이다.
이를 4k마다 적응하는 온라인 배분 실험과 혼동하지 않는다.

개발 자료는 E1~E3, 최종 확인은 원래 seed 21·22·23의 새로운 A 정책과 200k·400k로
구분한다. 개발에 사용한 과제 조합에 대한 새로운 정책 일반화이며 새로운 과제 조합의
외부 검증은 별도 단계다. 검사할 seed의 분기 결과를 보기 전에 다음 비교를 동결한다.

- Uniform, 개발 자료에서 정한 전역 Fixed, 시간별 Fixed.
- 공개 100사례의 Failure와 Progress.
- 실패율이 높은 두 과제에 각각 37.5%, 나머지 각각 12.5%를 배분하는 Failure Top2.
- 성공률·최근 진행량만 사용하는 작은 수치 예측기와, 경험 노출·과제 관계 같은 사전
  관측을 제한적으로 추가한 예측기. 모델·입력·정규화·튜닝은 새 원래 seed의 결과 전에 동결한다.

Failure Top2는 단 한 번의 성공 차이로 모든 추가 비중을 한 과제로 몰아주는 규칙의
약점을 확인하는 기준선이다. 동률은 고정된 과제 순서로 해소한다. 예측기가 고르는 후보는
기존 다섯 배분으로 제한하고 결과 bank의 점수나 rollout을 입력으로 제공하지 않는다.
실제 반응 label은 원래 seed 기준으로 분리한다. 분기 행을 무작위로 나누면 같은 출발
정책이 학습·검사 자료에 함께 들어가므로 허용하지 않는다.
TD error나 reward를 입력으로 추가한다면 과제마다 분포가 다르므로 raw 크기만으로
과제 순위를 정하지 않는다. 개발 자료에서 정한 과제별 보정과 그 계산 비용을 고정한다.

여섯 실행 조건은 다섯 고정 후보와 context별 Failure Top2다. 3 원래 seed × 2시점 ×
6조건 × 3 후속 반복 = 최대 108분기, 4.32M이며 사전학습 1.20M를 더해 5.52M이다.
고정 후보를 택하는 여러 규칙은 같은 분기 결과를 조회하므로 중복 실행할 필요가 없다.
단, 모든 후보를 실행한 비용은 연구용 label 수집 비용으로 기록하고 운영 선택기의
비용처럼 40k만 제시하지 않는다.

E1~E3의 독립 context 수는 작다. 복잡한 모델이나 LLM을 학습할 충분한 자료가 확보됐다고
간주하지 않는다. 추가 정보 모델이 단순 수치 모델을 못 이기면 그 결과를 받아들인다.
학습 진행량 기반 curriculum과 학습 가치에 따른 선택은 이미 연구됐다.
현재 Progress 규칙이나 단순 TD-error 규칙을 정식 ALP-GMM·PLR 구현이라고 부르지 않는다.
[ALP-GMM](https://arxiv.org/abs/1910.07224), [Prioritized Level Replay](https://proceedings.mlr.press/v139/jiang21b.html)

온라인 적응은 이 검증 이후 별도 설계한다. 중간 진단, 후보 시험 분기, 모델 호출 비용을
반드시 더하고, 같은 학습 step 수의 비교와 같은 총 환경 상호작용 예산의 비교를 구분한다.
4k 시범 연습이 40k의 가치를 예측한다고 가정하지 않는다. 이미 20k와 40k에서 순위가
달라졌으므로 짧은 probe의 예측력을 먼저 검증해야 한다.

## 공통 측정과 판단 규칙

각 본 실험은 소스·설정·의존성·seed 계층·입력 bank·비용·실패 기록을 동결한다.
학습기는 06의 SAC와 동일하게 유지하고, R의 replay 개입만 명시적 예외다.
전체 learner와 optimizer·entropy·replay·counter·RNG를 복원하며 분기 warm-up을 반복하지 않는다.
평가가 학습 RNG나 replay를 변경하지 않는지 검증한다. 공개 진단과 결과 평가는 과제당
100개로 늘리고 서로 다른 bank를 사용한다. 100회도 작은 차이를 확정하는 충분한 표본이라고
가정하지 않는다. 모든 새 평가 bank의 생성 seed와 실제 초기 상태 hash를 저장한다.

주 지표는 +40k의 네 과제 동일 가중 평균, 시작점 대비 Gain, U 대비 ExtraGain이다.
최악 과제 성공률과 시작점 대비 최대 하락폭을 함께 본다. U보다 덜 하락한 것을 절대 개선으로
부르지 않는다. +20k는 보조 시점이며, 전체 곡선이나 AUC를 세 점만으로 주장하지 않는다.
E2에서는 사전에 정한 DO 성공률 대비가 주 지표이고 나머지가 보조다.
이 설계가 비교하는 것은 지정한 유한한 배분 후보들이다. 연속적인 모든 배분 비율 중
최적값이나 다섯 후보 밖의 선택 가능성을 확인했다고 주장하지 않는다.

원래 seed마다 checkpoint·후속 반복을 묶어 보고한다. 평가 오차는 같은 과제의 평가 상태를
배분과 seed 전체에 걸쳐 공동 재표집하는 짝지은 분석으로, 학습 변동은 원래 seed 수준의
집계로 구분한다. seed와 평가 상태는 교차된 축이므로 90분기나 수만 episode를 독립 원래
seed로 간주하지 않는다. 원래 seed가 세 개뿐인 신뢰구간과 검정은 매우 제한적이다.
개별 seed 효과와 범위를 우선 제시하고, 더 많은 원래 seed를 확보한 확인 단계에서
계층·교차 구조를 보존한 불확실성 추정을 확장한다.
[Deep RL at the Edge of the Statistical Precipice](https://arxiv.org/abs/2108.13264)

개발 의사결정용 실용 차이는 macro 2%p, E2의 DO 5%p로 제안한다. 관측 평균이 이 크기
이상이고 원래 seed 세 개 중 적어도 두 개에서 방향이 같으면 다음 확인 실험 후보로 삼는다.
이는 검정 유의수준이나 발견 선언 기준이 아니다. 모든 효과와 상반되는 seed를 함께 공개하며,
순위 변화 자체보다 남겨둔 반복에서 유지되는 선택 이득을 본다.

| 결과 | 다음 판단 |
| --- | --- |
| 새 진단에서 Failure 선택이 바뀌고 성능도 좋아짐 | 실패율 자체의 한계와 측정 잡음의 영향을 분리하고 강한 Failure 기준선을 유지 |
| 모든 context에서 같은 배분이 충분함 | 고정 배분의 결과로 정리하며 적응형 선택기의 필요성을 주장하지 않음 |
| 시간별 Fixed만으로 설명됨 | 학습 시점별 schedule을 강한 기준선으로 채택 |
| 조건별 차이가 후속 반복에서 사라짐 | 불안정한 label로 선택기를 학습하지 않고 측정·변동을 보고 |
| E2에서 목표 연습량을 고정해도 차이가 유지됨 | 과제 간 자원 교환의 효과를 지지하되 직접 전이로 단정하지 않음 |
| B에서 유지되고 C에서 약해짐 | 구성 의존성으로 보고하며 난이도·출발 성능 변화도 함께 점검 |
| 여러 구성에서 예측 가능한 선택 이득이 남음 | 새 원래 seed의 E4로 넘어가고 더 넓은 과제 집합·다른 환경의 외부 검증을 준비 |

## 뒤로 미룰 실험과 보존 방식

seed 901의 400k checkpoint만 추가 분기하는 실험은 15분기·600k로 빠르게 시점 차이를 볼
수 있지만 독립 사전학습 정책의 부족을 해결하지 못한다. 그래서 E1의 대체로 삼지 않는다.
40k 이후 80k까지의 연장은 회복과 예산 의존성을 조사할 수 있으나, 사후에 성능이 낮은
분기만 연장하지 않고 정한 조건 전체에 동일하게 적용하는 별도 설계가 필요하다.

sparse reward, reward 정규화, 모델 구조 변경, 새로운 벤치마크, LLM 감독자를 동시에
도입하면 기존 관찰과 비교하기 어려워진다. 각각의 필요성을 앞 단계로 좁힌 뒤 별도 버전과
동일 예산 대조군으로 다룬다. 단순 과제 관계를 설명하는 이름 정보만으로 선택기가 유리하다고
가정하지 않으며, 과제 ID·구조 관계 같은 같은 정보를 받는 수치 기준선도 비교해야 한다.

새 실험 구현은 순서에 따라 `09_fresh_evaluation_audit_v1`,
`10_independent_seed_checkpoint_study_v1` 같은 독립 폴더에 둔다. 뒤의 번호는 실제 실행
순서에 맞춰 확정한다. 08에는 계획만 두며 이전 버전은 새 코드에서 역으로 import하지 않는다.
각 검증과 본 실행은 새 출력 폴더를 쓰고 소스 사본·hash, 실제 비용, 실패한 실행을 남긴다.

예산 산술은 아래 명령으로 재계산한다. 이 명령은 정책을 학습하거나 평가하지 않는다.

```powershell
& 'C:\Python312\python.exe' '.\08_followup_experiment_design_v1\calculate_budget.py'
```

결과는 매번 새 `results/<UTC>_budget_review_<ID>/`에 계획 사본, 입력 hash, 검토 기록 및
예산 CSV로 저장된다. 이후 조건을 바꾸면 전달된 이 설계를 덮어쓰지 않고 새 설계 버전을 만든다.

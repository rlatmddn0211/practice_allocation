# 공개 범위와 재현 안내

이번 공개는 후보 검증의 정의·설계·측정 코드·결과표·해석·검산 기록을 GitHub 저장소에서 함께 읽을 수 있게 하는 작업이다. 23–37번의 기존 독립 버전을 보존하고 38번에 후보별 역할·검증 결과·후속 판단 안내를 추가했다.

| 범위 | 공개 내용 |
| --- | --- |
| 23–25 | 8개 후보 설계, ⑦ 분석, 최초 근거 기록 |
| 26–30 | critic·성공 보존·gradient·가소성·노출·경험 지표 구현과 검증 결과 |
| 31–33 | ⑤ 새 진단, ⑧ 강도·순서 실험, 자동 실행 계획·완료 기록·CSV·분석·검산 |
| 34–37 | 중간 검토, ⑤ 완료 후 전체 검토, ⑧ 완료 후 통합 분석과 그림 |
| 38 | 후보별 역할·결과·해결을 위한 검증 방향, 공개 무결성 기록 |

기존 `.gitignore`가 제외하는 대형 모델·replay·배열 파일, 가상환경, 캐시, mutable 상태 로그 등은 로컬에 보존한다. 이번 Git 커밋은 **모든 학습 checkpoint까지 포함한 전체 실행 환경 백업**을 뜻하지 않는다. 기존 E0–E2 원자료·checkpoint의 별도 보관은 [20번 GitHub Release 안내](../20_e0_e2_github_publication_v1/README.md)를 따른다. ⑧의 새 대형 checkpoint를 그 이전 Release에 포함됐다고 주장하지 않는다.

GitHub에서는 README·후보 안내·보고서·CSV·검산 요약·그림을 상대 링크로 읽을 수 있다. 원래 실행 JSON·CSV에 남은 `C:`/`D:` 절대 경로와 파일 hash는 과거 증거를 보존하기 위해 수정하지 않는다. 다른 컴퓨터에서 전체 분석·학습을 재실행하려면 해당 경로를 읽는 부분의 명시적 매핑과 제외된 원본 모델·replay가 필요하다. 보고서를 열람할 수 있다는 것과 깨끗한 clone만으로 모든 원시 실험을 재실행할 수 있다는 것은 별개다.

각 과거 문서의 “진행 중/미실행”은 작성 당시의 기록이다. 최신 실행 상태와 판정은 [37번 근거 기록](../37_f08_integrated_candidate_review_v1/factor_status_ko.md), 후속 판단은 [38번 후보 안내](candidate_guide_ko.md)를 따른다. 과거 판정을 덮어써 결과가 처음부터 알려져 있었던 것처럼 만들지 않는다.

공개 점검은 새 결과 폴더에 소스 snapshot/hash, 주요 입력 hash, 문서 링크, Git에 stage된 파일의 bytes 확인, 실제 소요 시간을 기록한다. 원 보고서의 과학적 검산을 재사용하며 새 학습·환경 평가를 실행하지 않는다. 사용자 요청에 따라 이 기록과 안내를 `origin/main`에 게시한다.

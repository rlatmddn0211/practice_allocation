# E0–E3 무인 순차 실행

실행 결과 저장 위치는 `D:\robot_practice_allocation_runs`다. 검증 도중 C의 여유 공간이 약 1GB로 줄어 보호 대기가 작동했고, 사용자가 승인한 D 전용 폴더로 **새 실행만** 전환했다. 코드와 검증된 기존 결과는 C의 저장소에 그대로 있다. D 안에서도 09~13번 버전별 폴더 구조를 유지한다. `ACTIVE_CAMPAIGN.json`이 D의 현재 캠페인을 가리킨다.

사용자가 2026-10-08에 E0부터 E3까지 구현과 자동 실행을 승인했다. 기존 08 설계 문서는 보존하며, 09·10·11·12에 독립 구현을 두고 이 폴더의 큐가 순차 실행한다. 좋은 효과를 얻었다는 조건으로 진행을 결정하지 않는다. R·E4는 실행하지 않는다.

| 단계 | 새 학습 step | 40k 분기 | 평가 episode |
|---|---:|---:|---:|
| E0 | 0 | 0 | 10,800 |
| E1 | 4,800,000 | 90 | 79,200 |
| E2 | 1,080,000 | 27 | 22,800 |
| E3 | 4,800,000 | 90 | 81,600 |
| 합계 | 10,680,000 | 207 | 194,400 |

이는 본 실험 예산이다. 기술 검증·실패·재시도 비용은 별도 결과 폴더와 비용 ledger에 남긴다. 실제 GPU/환경 속도를 기준으로 약 45–66시간에 작업 시작 및 저장 비용이 더해질 수 있다. 완료 시각을 보장하는 예약은 아니다.

`campaign.py`는 1,051개 원자 작업과 입력 의존성을 동결한다. bank 생성, 모델 초기화, 20k 학습, 평가, 규칙 동결, 분석을 별도 프로세스에서 처리한다. E2가 E1의 정확한 200k 부모를 자동으로 받고, 마지막 단계 분석까지 수행한다. 각 구현의 SAC·수집·환경·평가 코어 파일은 06과 동일하다. 구현 폴더끼리 Python 코드를 import하지 않으며 입력은 hash가 확인된 데이터 파일로만 교환한다.

`plan.json`과 소스 hash는 실행 도중 바꾸지 않는다. 각 작업은 새로운 출력 폴더, 소스 사본, 설정, 전체 의존성 목록, 학습/평가 CSV, 실제 비용과 완료 결과를 남긴다. 완료 기록의 hash를 검증한 뒤 다음 작업으로 진행한다. 체크포인트는 모델·optimizer·entropy·replay·collector·RNG 전체이며 replay만 LZMA로 무손실 압축한다. 기존 체크포인트나 실패한 폴더를 지우거나 덮어쓰지 않는다.

운영 상태인 `STATUS.json`만 갱신한다. 과학적 결과는 완료 후 덮어쓰지 않는다. 평가에 사용한 100개 공개 사례와 100개 결과 사례는 분리하고, 기존 bank와 학습 reset의 상태 hash를 확인한다. 학습 중에도 bank와의 겹침을 검사한다.

재시작 시 완료된 20k 작업은 반복하지 않는다. 관리자가 종료되어도 살아 있는 작업 프로세스를 인계한다. 작업 자체가 종료되면 새 출력 폴더에서 마지막 완료 부모부터 같은 난수 상태로 다시 수행한다. 한 작업당 최대 3회이며 수치 오류, hash/과제 매핑/예산 불일치는 중단 사유다. 강제 종료 직전 비용 계수가 저장되지 않았다면 비용이 완전히 측정되지 않았음을 표시한다. 여유 공간이 1.5GB 미만이면 결과를 지우지 않고 공간 확보를 기다린다.

Windows 작업 스케줄러는 현재 사용자 로그인 때와 5분 간격으로 큐를 확인한다. `pythonw.exe`로 창 없이 실행하고, 파일 잠금으로 중복 실행을 막는다. 활성 관리자는 시스템 절전을 억제하고 완료되면 해제한다. PC가 꺼져 있으면 계산할 수 없으며 재부팅 후에는 이 사용자로 로그인해야 자동 재개된다. 완료된 큐는 재호출되어도 새 실험을 시작하지 않는다.

현재 실행 상태:

```powershell
13_e0_e3_autonomous_queue_v1\.venv\Scripts\python.exe 13_e0_e3_autonomous_queue_v1/campaign.py status
```

`ACTIVE_CAMPAIGN.json`이 현재 캠페인 경로를 가리킨다. 해당 폴더의 `STATUS.json`, `events.jsonl`, `completed/`, `attempts/`를 보면 현재 작업과 재시도 이력이 나온다. 단계별 분석 완료 시 그 작업 폴더에 `REPORT.md`, `analysis.json`, 대비 CSV가 생성되고 최종 `campaign_summary.json`이 보고서 경로와 총비용을 정리한다.

수동 복구는 같은 캠페인에 `campaign.py run --campaign <경로>`를 실행한다. 새 `prepare`는 별도 전체 실험을 만들므로 기존 큐 재시작에 사용하지 않는다. 의도적으로 작업 경계에서 중단하려면 캠페인 폴더에 빈 `STOP_AFTER_JOB` 파일을 둔다. 이를 제거하면 다음 예약 호출에서 재개한다. 무결성 오류는 자동으로 숨기거나 우회하지 않는다.

`scaffold.py`, `sync_development_copies.py`, `prepare_runtime.py`는 최초 개발/설치 이력이며 전달 후 기존 버전에 다시 실행하지 않는다. 런타임은 새 `.venv`에 기존 검증된 의존성 배포 파일을 hash 확인하여 복사했으며 시스템의 고정 CUDA PyTorch를 사용한다. 의존성 충돌 여부는 `pip check`, 실제 계산은 CUDA 검증으로 확인한다.

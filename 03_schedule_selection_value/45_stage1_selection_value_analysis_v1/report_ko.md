현재 과제 구성에서는 여러 과제가 동시에 개선 가능한 상태를 안정적으로 확보했는지도 다시 확인할 필요가 있다.

**저성능 부모의 학습 상태에는 별도로 점검할 단서가 있다.**

이는 단일 업데이트의 로그 비교이므로 시간 추이에 대한 점검 대상으로 남긴다.

**다음 판단.**
현재 근거로 2·3단계를 그대로 확대하거나 진단 규칙이 유효하다고 취급할 수 없다.
우선 이미 저장된 학습 로그로 출발 상태의 안정성, BP 변화와 기존 능력 손실의 시간 추이를 확인하는 것이 타당하다.
특히 41013은 설정을 바꿔 재학습하기 전에 학습 경로를 점검할 대상이다.
기존 로그의 학습 성공은 보존된 checkpoint의 독립 평가 성공률과 같지 않으므로 둘을 대체하지 않는다.

그 후에도 중간 상태별 전환 가치를 조사할 이유가 남으면, 같은 8k 상태에서의 소규모 실제 유지·전환을
**1단계 미통과 후의 별도 탐색**으로 명시하고 목적·규모·종료 기준을 먼저 정해야 한다.
기존 유지/교대/혼합 최종 점수를 이어 붙여 전환 효과를 만들지 않는다.
3단계 비용 회수 비교는 아직 근거가 부족하다. 이 문서에서 새로운 환경 실행을 시작하거나 예약하지 않았다.

**비용과 재현 범위.**
실제 연구 학습 2,200,000 step, 최종 평가 4,797,719 step, 합계 6,997,719 환경 step이다.
SAC update는 2,195,000회다. 부모마다 처음 1,000 step은 학습 준비 구간이다.
연구 작업 wall time의 합은 약 13.224시간, CPU time의 합은 약 6.942시간이며, 작업 사이 대기나 수정 인계 시간과 구분한다.
GPU busy time은 미측정이다. 44번 기술 검사의 33,396 환경 step과 이전 42번 기술 비용은 연구 결과와 별도 기록이다.
이번 재분석은 환경 step·SAC update 0이며, 실행 시간은 각 결과의 `analysis_wall_seconds`에 기록했다.
